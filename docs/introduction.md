## 一、项目速览

| 项 | 内容 |
|---|---|
| **名称** | AgentMotion |
| **一句话定位** | 一句话出片 · 纯代码视频生成统一框架 |

| **项目类型** | 面向 AI Agent 的视频创作技能包（Agent Skill） |

| **状态** | 已公开开源，CI 自动测试通过 |

**一段话介绍**：

AgentMotion 让大模型用「代码逐帧绘制」的方式渲染出真正的 MP4 视频——不生成任何图片素材、不调用扩散视频模型。它的核心是一个简洁到极致的原则：**每一帧都是帧号的纯函数（`frame = f(t)`）**。因为这个原则，画面变得完全确定：可以逐帧自检、可以并行渲染、可以任意复现。项目把社区里散落的知识收敛为「一个入口 → 两种后端 → 15 种风格 → 一条质检流水线」，让任何 AI Agent 都能稳定地产出可交付的视频。

## 二、它到底是什么

### 2.1 一句话说清

**传统视频**：人用剪辑软件、或用 AI 扩散模型生成画面。
**AgentMotion**：AI 用代码「算」出每一帧画面，再交给浏览器逐帧截图、编码成视频。

### 2.2 三个"不"

1. **不生成素材**——没有 AI 生图、没有字体文件、没有贴图，一切视觉都由代码实时计算。
2. **不调用扩散模型**——不走 Wan / Hunyuan / LTX 等生成式视频路线，因此结果可复现、可审计、无版权争议。
3. **不依赖剪辑软件**——整条时间线就是一份代码，改一行代码就改一个镜头。

### 2.3 一个关键前提

它面向的是**具备强推理能力的模型**（如 Claude Opus 这类）。社区实践已经证明：只要模型够强，再加上一套 Node / Chrome / ffmpeg 的环境，"一句话"就能让它自己写出渲染整支影片的代码。AgentMotion 做的，是把这件事从"少数人的技巧"变成"人人可复制的流程"。

## 三、为什么做这个项目（背景与动机）

### 3.1 社区已经验证了可行性

过去一年，社区里出现了大量"用 Claude Opus 一句话生成代码视频"的案例：科普动画、产品宣传片、数据盘点、艺术短片……方法论的结论是一致的：

> **强推理模型 + Node/Chrome/ffmpeg = 模型能自己渲染出 MP4。**

### 3.2 但知识是散的

问题在于，这些宝贵的知识分散在十几个独立的技能包、提示词合集、案例库和个人笔记里：

- 有的讲"怎么写提示词"，
- 有的讲"逐帧手绘怎么画"，
- 有的讲"Remotion 怎么用"，
- 有的讲"配乐怎么跟节拍对齐"……

它们**彼此不知道对方存在**，模型每次都要重新摸索，效果高度依赖运气。

### 3.3 缺一个统一的入口

AgentMotion 要解决的，不是"再发明一个渲染器"，而是**把这条链路收敛成一个入口**：选后端、选风格、走流程、过质检，一步不落。这正是"框架"二字的含义——它不是某个单一技巧，而是让所有技巧能协同工作的骨架。

## 四、核心理念：帧 = f(t)

这是整个项目的地基，值得单独讲清楚。

### 4.1 什么是"帧 = f(t)"

影片的每一帧，都是**帧号的纯函数**：给定帧号 `t`，就唯一确定这一帧长什么样。

- 不用 `Math.random()`（改用带种子的随机数，同一帧永远得到同样的"随机"结果）；
- 不用 `Date.now()`（时间只能来自帧号）；
- 不用累积状态（没有"上一帧留下的东西"）。

### 4.2 为什么它如此重要

因为"帧 = f(t)"，三个能力同时成立：

1. **可并行**：帧与帧之间没有依赖，可以用 6 个、10 个、100 个 worker 同时出帧，渲染速度线性提升。
2. **可自检**：任意时刻都能单独截出一帧，和分镜逐条核对——不需要为了检查第 90 帧而把整片渲一遍。
3. **可复现**：同一份代码，今天渲和明天渲，结果一模一样。这对开源、协作、交付都至关重要。

一句话：**确定性，是"AI 写代码"这件事能稳定产出的前提。** 如果 AI 写的画面随机漂移，它就永远无法被验证、被信任。

## 五、核心能力

### 5.1 双渲染后端

| 后端 | 适合 | 优势 |
|---|---|---|
| **单文件 HTML Canvas**（默认） | 短片、零素材、插画/手绘/风格化 | 依赖最少，AI 一遍写对的概率最高 |
| **React + Remotion** | 数据驱动、批量个性化、烧录字幕、图表/3D | 组件生态强，一条数据 = 一支片 |

同一套风格配方、同一条质检流程，两种后端通用。

### 5.2 15 种商用级风格配方

每种风格都拆到「**调色板 / 技法 / 运动规律 / 避坑**」四段粒度——AI 照做即可复现质感，而不是"凭感觉画"。见第七节全表。

### 5.3 确定性渲染器

一个 `render.mjs`，三条命令覆盖全部渲染需求：

- 出**全片 MP4**（多 worker 并行）
- 出**指定时刻静帧**（自检用）
- 出 **contact sheet 拼图**（导演视角总览）

配套还有**环境体检**脚本和**编码断言**脚本，从环境到成品全程可验证。

### 5.4 音画同源

画面和配乐读**同一份时间数据**（段落/镜头/事件三张表），因此镜头切点**天然落在节拍上**，不需要后期对轨。这是"代码做视频"相比手工剪辑的一个结构性优势。

### 5.5 完整质检流水线

自检先于渲染、静帧先于全片：

> 分镜符合度检查（静帧逐条核对）→ 导演轮（拼图看节奏/景别/死帧）→ 全片渲染 → 编码断言。

### 5.6 宿主无关

它既是一个标准的 **Agent Skill**（能被 Claude Code、WorkBuddy 等直接调用），也是一组**普通命令行工具**（任何有 shell 的 Agent、乃至人类自己都能用）。没有宿主锁定。

## 六、技术架构

```
┌─ 编排层  SKILL.md / AGENTS.md —— 选型决策 + 工作流 + 防翻车规则
├─ 工具层  scripts/ —— render.mjs(渲染) · env-check(体检) · probe(断言)
├─ 模板层  templates/ —— starter.html(帧=f(t) 骨架 + 相机 + 节拍系统)
├─ 知识层  references/ —— 工作流/分镜/技法/质检/音画/后端选型
└─ 风格层  styles/ —— 15 种风格配方
```

五个层次各司其职：**编排层**告诉 AI "先做什么后做什么"，**工具层**负责"真的渲染出来"，**模板层**给"第一块砖"，**知识层**教"怎么画才对"，**风格层**提供"不同的长相"。

## 八、从一句话到成片（工作流）

1. **读题** —— 推断片型（故事/讲解/盘点/数据片）、时长、画幅。
2. **选后端** —— 短片走 Canvas，数据驱动走 Remotion。
3. **选风格** —— 从 15 种配方里挑，或按主题推荐。
4. **分镜** —— 把节拍、镜头、事件写成三张数据表。
5. **搭骨架** —— 从模板起步，替换调色板与世界绘制。
6. **自检** —— 静帧核对分镜 → 拼图导演轮（至少两遍）。
7. **渲染** —— 多 worker 出全片 + 编码断言。
8. **交付** —— MP4 + 可播放的 HTML 源码。

全程不打断用户，只在完全没有主题时才提问。

## 九、典型使用场景

- **故事短片 / 绘本动画**：把一段文字变成逐帧手绘的短片。
- **科普讲解片**：30–90 秒，贴纸风或白板风，字幕烧录。
- **产品宣传片**：扁平矢量或玻璃拟态，一条代码改主题即复用。
- **数据盘点（Wrapped 式）**：一张数据表 → 一人一支个性化视频，可批量渲染成千上万份。
- **风格目录片**：像"一模型十五风格"那样的 showcase。
- **无缝循环 GIF**：像素风、Synthwave、液态流动，适合做头像、封面、氛围动图。

## 十、差异化与上游关系

### 10.1 与现有方案的区别

- **不是又一个提示词库**：提示词解决"怎么说"，AgentMotion 解决"怎么做到底"。
- **不是又一个渲染器**：渲染器只是它的一层，真正的价值是"编排 + 知识 + 质检"的整体。
- **不是宿主绑定**：既服务 Agent，也服务人类 CLI。

### 10.2 诚实的致谢

项目受社区公开方法启发（"一句话出片"的提示词案例库、PDoomVideo / ClaudeAnimationBase 的手绘动画流水线、Remotion 官方生态等），但**所有代码与文档均为原创重写**，未复制上游受版权保护的内容。详细致谢见 `docs/architecture.md`。

## 十一、开源与社区

- **协议**：MIT，自由使用、修改、商用。
- **质量门槛**：任何 PR 需通过"环境体检 + 渲染 + 编码断言"；新风格配方需含四段式结构。
- **安全承诺**：代码纯原创、零素材、可审计。
- **路线图**：切点节拍自动校验、文字碰撞检测、Remotion 模板脚手架、配乐合成模板、MCP Server 封装。
- **参与方式**：欢迎贡献新风格、新工具、新案例。
